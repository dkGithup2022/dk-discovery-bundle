# Design References Workflow v1 — /dk-discovery-bundle:design-references

디자인 인계 2단계(레퍼런스 보내기)의 재료를 만든다:
분위기 선언에 맞는 **톤 레퍼런스**를 찾아 캡처해 로컬에 ~15곳 보관하고,
그중 디자인 도구에 실제로 보낼 ~5곳을 유저와 고른다.

로컬에 많이, 전송은 적게 — 인 이유: 후보가 많아야 고를 수 있고,
다 보내면 디자인이 평균을 내버려 톤이 흐려진다.

## Step 1 — 후보 제안·확정 (대화)

```
분위기 선언을 기준으로 후보 12~18곳을 제안한다. 각 후보에 한 줄 이유
("이 서비스의 어떤 점이 우리 분위기와 닿는가")를 단다.
후보의 성격: 경쟁사가 아니라 닮고 싶은 톤. 도메인이 달라도 된다
(잡지, 콘텐츠 구독, 편집숍 등 — 분위기가 기준).
유저가 더하고 빼고 확정한다. Add: 인자로 받은 후보는 목록에 우선 포함.
```

## Step 2 — 캡처 (자율 실행 가능)

```
확정된 후보를 순서대로 방문해 캡처한다. capture-guide.md의 규칙을 따른다
(줌아웃 — 내용이 파악될 정도로, 쿠키 배너 거부, 컷별 URL 기록, 부산물 정리).

사이트당 2~3장: 첫 화면 + 콘텐츠 상세(아티클·상품 등 대표 화면) (+ 목록 화면).
각 사이트마다 shots.md: 파일·화면 설명·URL·"우리 분위기와 닿는 점" 한 줄.
접근 실패(차단·회원제)한 곳은 기록하고 넘어간다 — 후보가 많은 이유다.
```

## Step 3 — 선별 (대화)

```
캡처를 유저에게 보여주고 (파일 경로 안내 또는 열람 페이지) 전송할 ~5곳을 고른다.
선정·탈락 이유를 한 줄씩 기록한다 — 다음 프로젝트에서 재사용할 수 있는 취향 기록이 된다.
선별 결과를 selection.md에 정리: 전송 목록 + 각각 "디자인에게 이 레퍼런스에서
봐달라고 할 점" 한 줄 (2단계 프롬프트에 곁들일 문구가 된다).
```

## Output

```
{run 디렉토리}/design_handoff/
  references/
    {site}/  ← 캡처 png + shots.md (사이트당)
    selection.md  ← 전송 5곳 + 봐달라고 할 점 + 선정·탈락 기록
  handoff.json (갱신 — references_ready: true, 전송 목록)
```

## Commit

```
git add design_handoff/references/ → staged 검증 (git/git-verification.md)
사이트 묶음 단위로 커밋: "design(references): {N}곳 캡처 — {요약}"
선별 후: "design(references): 전송 {M}곳 선별"
```
