# 와이어프레임 가이드 — 와이어프레임이란 무엇이고 어떤 모양인가

discovery-wireframe 워크플로가 만드는 산출물의 정의서다. 워크플로(v1-wireframe-workflow.md)는
"어떤 순서로 만드는가"를, 이 문서는 "무엇을 만드는가"를 다룬다.

## 목적

와이어프레임은 **페이지 하나 안에서 무엇이 어디에 놓이는지를 색과 장식 없이 보여주는 저해상도 그림**이다.
사이트맵의 페이지별 섹션 목록을 위에서 아래로 박스로 쌓고, 박스마다 섹션 번호와 이름을 라벨로 붙인다.

사이트맵의 섹션 목록은 "P4 모임 페이지에는 헤더, 모임 정보, 행동 버튼, 탭 바, 탭 내용이 이 순서로 쌓인다"까지만 적는다.
각 섹션이 화면에서 얼마나 큰 자리를 차지하는지, 섹션 안에서 버튼과 글이 어떻게 놓이는지는 적지 않는다.
와이어프레임은 이것을 그림으로 옮긴다.

이 한 장으로 하는 일:

```
1. 섹션 목록이 실제 화면에 들어가는지 확인한다
   목록으로는 문제없어 보여도, 박스로 쌓으면 첫 화면에 핵심 행동 버튼이 보이지 않을 만큼
   위쪽 섹션이 길다는 것이 드러난다.
   예: P4 모임 페이지에서 모임 정보 섹션이 길면 가입 신청 버튼(P4-3)이 스크롤해야 보인다.
2. 화면 상태마다 무엇이 바뀌는지 정한다
   유저 흐름에서 나온 상태(비로그인, 빈 목록, 오류 등)마다 기본 모양에서 어느 섹션이 어떻게 바뀌는지 그린다.
   예: P9 내 모임 목록에 가입한 모임이 없으면 목록 자리에 무엇을 보여주고 어디로 안내하는가.
3. 흐름을 화면 위에서 따라가 본다
   유저 흐름의 순서대로 화면을 늘어놓고 화살표로 이으면(와이어플로), 흐름의 "가입 신청을 누른다"가
   화면의 어느 섹션에서 일어나는지 눈으로 확인할 수 있다.
4. 클로드 디자인에 넘길 뼈대가 된다
   이 HTML 파일을 클로드 디자인 3단계에 첨부하면, 요청이 "와이어프레임을 만들어달라"에서
   "이 와이어프레임을 다듬어달라"로 바뀐다. 클로드 디자인이 배치를 새로 정하지 않고,
   우리가 정한 배치 위에서 간격과 크기를 다듬게 된다.
```

와이어프레임이 다루지 않는 것:

```
페이지 목록과 포함 관계 — 어떤 페이지가 있고 어느 페이지 아래에 있는지는 사이트맵이 다룬다.
  와이어프레임은 사이트맵에 있는 페이지와 섹션만 그린다
과업의 순서 — 유저가 어떤 순서로 화면을 거치는지는 유저 흐름이 다룬다.
  와이어플로는 유저 흐름의 순서를 그대로 옮겨 화면을 잇기만 하고, 순서를 새로 정하지 않는다
색, 글꼴, 이미지, 실제 문장 — 이것들은 클로드 디자인 4단계(색·테마) 이후에 정한다.
  ui-spec의 전역 분위기도 이 단계에서 쓰지 않는다
정확한 크기와 간격 — 픽셀 단위 여백과 글자 크기는 클로드 디자인이 다듬는다.
  와이어프레임은 섹션끼리의 상대적인 크기(이 섹션이 저 섹션보다 크다)와 놓이는 위치까지만 정한다
```

세 산출물의 경계를 한 줄씩 정리하면 이렇다 (유저 흐름 가이드의 같은 표와 같다).

| 산출물 | 답하는 질문 |
|--------|-----------|
| 사이트맵 | 어떤 페이지가 있고, 어떻게 묶여 있고, 각 페이지에 어떤 섹션이 위에서 아래로 쌓이는가 |
| 유저 흐름 | 과업 하나를 하는 동안 어떤 화면을 어떤 순서로 거치고, 어디서 갈라지고, 실패하면 어디로 가는가 |
| 와이어프레임 | 화면 하나 안에서 섹션과 요소가 어디에 어떤 크기로 놓이는가 |

### 해상도

와이어프레임은 얼마나 자세히 그리느냐에 따라 저해상도·중해상도·고해상도로 나뉜다.
이 단계는 저해상도만 그린다.

| 해상도 | 그리는 것 | 누가 만드는가 |
|--------|----------|-------------|
| 저해상도 | 섹션 박스, 라벨, 요소 자리(이미지 자리, 글 줄, 버튼 칸) | 이 단계 |
| 중해상도 | 실제 문구, 간격과 크기 조정, 컴포넌트 모양 | 클로드 디자인 3단계 (이 단계의 결과를 다듬는다) |
| 고해상도 | 색, 글꼴, 이미지, 아이콘 | 클로드 디자인 4단계 이후 (시안) |

저해상도로 멈추는 이유: 색과 장식이 들어가면 보는 사람이 배치보다 겉모습을 평가하게 된다.
이 단계에서 유저가 okay하는 대상은 배치다.

## 모양

study 레퍼런스(`study/wireframe/example_2.png`)처럼 페이지마다 섹션을 위에서 아래로 쌓고, 섹션마다 라벨을 붙인다.

```
 P4 모임 페이지 (상세, 템플릿)                P4 모임 페이지 · 비로그인
 ┌─ P4-1 헤더 [공통] ─────────────        ┌─ P4-1 헤더 [공통] ─────────────
 │ ‹ 뒤로가기  페이지 이름  (공유)          │ (기본 모양과 같음)
 ├─ P4-2 모임 정보 (기능 6) ──────        ├─ P4-2 모임 정보 ───────────────
 │ ▬▬▬ 모임 이름                          │ (기본 모양과 같음)
 │ ─────── 소개                            ┆
 │ ── 지역 · 멤버 수 · 가입 조건            ┆ 바뀐 섹션 ↓
 ├─ P4-3 행동 버튼 (기능 4, 11) ───        ├┄ P4-3 행동 버튼 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 │ [ 팔로우 ]  [■ 가입 신청 ]               ┆ [■ 로그인하고 가입 신청 ]
 ├─ P4-4 탭 바 ────────────────           ┆ ··· 누르면 X1 로그인·가입 (F4)
 │ 아카이브(기본) │ 이벤트 │ 게시판 │ 멤버    ├─ P4-4 탭 바 ───────────────────
 ├─ P4-5 탭 내용 (기능 7) ─────────        │ (기본 모양과 같음)
 │ [╳] ─── 매거진 카드                      ├─ P4-5 탭 내용 ─────────────────
 │ [╳] ─── 매거진 카드                      │ (기본 모양과 같음)
 │ …                                       └────────────────────────────────
 └────────────────────────────────
```

왼쪽이 기본 모양, 오른쪽이 유저 흐름에서 나온 화면 상태 하나다.
프레임 제목의 괄호는 사이트맵 페이지 유형이다. " · " 뒤에는 화면 상태 이름만 온다.
상태 화면은 기본 모양에서 바뀐 섹션만 점선으로 그리고, 나머지 섹션은 박스와 라벨만 남긴다.

### 구성 요소

| 요소 | 설명 |
|------|------|
| 프레임 | 화면 하나의 테두리. 위에 페이지 번호, 이름, 유형을 적는다. 앱이면 휴대폰 화면 비율, 웹이면 데스크톱 화면 비율 |
| 섹션 박스 | 사이트맵 섹션 목록의 섹션 하나. 프레임 안에 위에서 아래로, 섹션 목록의 순서대로 쌓는다 |
| 섹션 라벨 | 섹션 박스 왼쪽 위에 붙는 섹션 번호와 이름 (P4-3 행동 버튼). 담는 기능 번호를 뒤에 작게 붙인다 |
| 요소 자리 | 섹션 안의 버튼, 글, 이미지, 입력 칸이 놓일 자리. 아래 "요소 자리 모양" 표의 모양으로 그린다 |
| 요소 이름 | 요소 자리 옆에 붙는 이름 (모임 이름, 가입 신청). 사이트맵 섹션 목록의 "담는 내용"에 적힌 말을 그대로 쓴다 |
| 공통 섹션 | 여러 페이지에 반복되는 섹션(헤더, 하단 탭). 한 번 그려 두고 각 페이지에서 같은 모양으로 다시 쓴다 |
| 상태 화면 | 같은 페이지의 다른 상태(비로그인, 빈 목록, 결과 없음, 오류, 불러오는 중, 대기 중). 기본 모양 옆에 둔다 |
| 동작 주석 | 화면만으로 알 수 없는 동작을 적는 메모 (누르면 어디로 가는가, 새로고침하면 입력값이 남는가) |
| 이동 화살표 | 와이어플로에서 한 화면의 섹션에서 다음 화면으로 가는 화살표. 화살표 위에 유저 행동을 적는다 |

### 요소 자리 모양

요소는 무엇이 놓이는지만 알아볼 수 있게 그린다. 실제 모양은 클로드 디자인이 정한다.

| 요소 | 그리는 모양 |
|------|-----------|
| 이미지 · 사진 · 동영상 | X자가 그어진 박스. 가로세로 비율만 맞춘다 |
| 제목 글 | 굵고 짧은 막대, 옆에 요소 이름 |
| 본문 글 | 가는 가로줄 여러 개 (줄 수로 글의 양을 나타낸다) |
| 버튼 | 테두리 박스 안에 누르는 행동의 이름 (가입 신청). 화면에서 가장 중요한 버튼 하나만 진한 회색으로 채운다 |
| 입력 칸 | 테두리 박스 위에 칸 이름 (자기소개) |
| 탭 · 메뉴 | 칸을 나눈 가로 막대, 칸마다 이름. 선택된 칸은 진한 회색 |
| 아이콘 | 작은 원 또는 작은 네모, 옆에 괄호로 이름 (공유) |
| 목록 · 카드 | 같은 카드 박스를 두세 번 반복하고 "…"을 붙인다. 카드 안은 이미지 자리와 글 줄만 그린다 |
| 비어 있는 자리 | 점선 박스 안에 무엇이 비었는지 적는다 (빈 목록 상태의 안내 자리) |

study 레퍼런스(`example_2.png`)는 라벨을 빨간 글자로 붙였다. 우리는 색을 쓰지 않으므로 라벨을 박스 왼쪽 위에 두어
위치로 구분한다. 레퍼런스의 로고 원, 슬라이드 화살표 같은 회사 소개 사이트 요소는 가져오지 않는다.

### 화면 상태

유저 흐름 단계가 넘긴 화면 상태 목록(user-flow.md의 "화면 상태 목록" 표)에 있는 상태를 모두 그린다.
상태 이름은 유저 흐름 가이드 "화면 상태" 표의 여섯 가지(비로그인, 빈 목록, 결과 없음, 오류, 불러오는 중, 대기 중)를 그대로 쓴다.

```
- 상태 화면은 기본 모양 프레임 바로 옆에 둔다. 같은 페이지의 모양들을 한 줄에 모아 비교하게 한다
- 바뀐 섹션만 점선 테두리로 그리고 요소 자리를 채운다. 바뀌지 않은 섹션은 박스와 라벨만 남기고
  "(기본 모양과 같음)"이라고 적는다
- 바뀐 섹션에는 동작 주석을 붙인다 — 그 상태에서 무엇을 누르면 어디로 가는지
  (예: "로그인하고 가입 신청"을 누르면 X1 로그인·가입으로 간다)
- 불러오는 중 상태는 요소 자리를 회색 막대로만 채운 모양으로 그린다
```

### 와이어플로

와이어플로는 유저 흐름 하나(F1, F2 …)를 화면 프레임으로 다시 그린 것이다. study 레퍼런스(`wireframe2.png`)처럼
화면 프레임을 흐름 순서대로 늘어놓고, 유저 흐름의 분기(마름모)와 화살표로 잇는다.

```
- 흐름 하나에 와이어플로 하나. 유저 흐름에 있는 흐름 번호를 그대로 쓴다
- 화살표는 유저가 행동하는 섹션에서 출발한다 (P4-3 행동 버튼 → M1 가입 신청서)
- 화살표 위에는 유저 흐름의 유저 입력 문구를 그대로 적는다 (가입 신청을 누른다).
  입력 글자 끝의 섹션 번호(P4-3)는 문구에서 빼고, 화살표가 출발하는 섹션으로 나타낸다
- 시작과 목표는 원으로, 화면이 아닌 단계와 외부 앱, 상태 화면이 없는 시스템 결과("결과: 신청 완료")는 작은 박스로,
  흐름 그림의 주석은 메모 박스로 옮긴다.
  흐름 그림의 노드 종류마다 무엇으로 옮기는지는 워크플로 7단계에 있다
- 분기는 마름모로 그리고, 나가는 화살표에 답(예 / 아니오)을 적는다
- 흐름이 상태 화면을 지나면 기본 모양 대신 그 상태 화면을 놓는다 (P4 모임 페이지 · 대기 중)
- 흐름에 없는 이동은 그리지 않는다. 페이지 사이의 이동 전체는 사이트맵 이동 표에 있다
- 다른 흐름을 거치는 곳은 그 흐름의 첫 화면 프레임 하나만 두고, 동작 주석에 그 흐름 번호를 적는다.
  그 흐름 안의 화면은 그 흐름의 와이어플로에서 그린다 (wireframe2.png가 인증 흐름을 작은 박스 하나로 줄여 둔 것과 같다)
- 와이어플로의 동작 주석은 점선 테두리와 회색 글자의 작은 메모 박스로 그려, 가리키는 마름모나 화살표 바로 옆에 둔다.
  가는 테두리의 단계 박스와 모양으로 구분하기 위해서다
  (wireframe2.png의 "새로고침하면 입력값이 남는다" 메모 박스). 페이지 프레임과 상태 화면 안의 동작 주석은
  위 그림처럼 섹션 아래 "···"로 시작하는 한 줄로 적는다
```

페이지 프레임 위에는 이동 화살표를 긋지 않는다. study 레퍼런스(`example_2.png`)는 메뉴에서 다른 페이지로 가는 화살표를
페이지 프레임 위에 그었지만, 우리는 화살표를 와이어플로에만 그린다.

사이트맵이 이동을 트리 그림이 아닌 이동 표에 따로 적는 것과 같은 이유로, 모든 페이지를 한 판에 늘어놓고
이동 표의 이동을 모두 화살표로 그리지 않는다. 화살표가 엉키면 사람이 판단할 수 없게 된다.

## 예시 — 크루 매거진 커뮤니티 앱

모임을 찾아 가입하고, 이벤트에 참석하고, 참석 기록을 매거진으로 남기는 앱이다.
사이트맵 가이드와 유저 흐름 가이드의 예시와 같은 서비스이고, 페이지 번호와 흐름 번호도 그 두 문서의 것을 그대로 쓴다.
P4 모임 페이지의 섹션 다섯 개는 사이트맵 가이드 "페이지별 섹션 목록"의 예시와 같다.
공통 섹션은 헤더와 하단 탭 두 개라고 가정한다. P9 내 모임 목록과 M1 가입 신청서의 섹션 구성,
그리고 기능 번호는 설명을 위해 가정한 값이다. 실제 와이어프레임에서는 사이트맵에 적힌 섹션과 번호만 쓴다.

공통 섹션을 먼저 그린다.

```
 헤더 [공통]                              하단 탭 [공통]
 ┌──────────────────────────             ┌──────────────────────────
 │ ‹ 뒤로가기   페이지 이름   (공유)         │ (홈) │ (모임 찾기) │ (MY)
 └──────────────────────────             └──────────────────────────
 ··· 1층 탭 화면에서는 뒤로가기가 없다      ··· 탭 화면(P1, P3, P8)에만 붙는다
```

P4 모임 페이지의 기본 모양과 비로그인 상태는 위 "모양"의 그림과 같다.
P4의 섹션 목록에는 하단 탭이 없으므로 P4에는 하단 탭을 그리지 않는다. 섹션 목록에 없는 섹션을 더 그려야 할 것 같으면
그리지 않고 사이트맵에 추가할 후보로 적는다.

유저 흐름에서 넘어온 화면 상태 중 P9 내 모임 목록 · 빈 목록을 그리면 이렇다.

```
 P9 내 모임 목록 (상세)                    P9 내 모임 목록 · 빈 목록
 ┌─ P9-1 헤더 [공통] ─────────────        ┌─ P9-1 헤더 [공통] ─────────────
 │ ‹ 뒤로가기   페이지 이름   (공유)       │ (기본 모양과 같음)
 ├─ P9-2 모임 목록 (기능 5) ──────        ├┄ P9-2 모임 목록 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 │ [╳] ▬▬ 모임 이름 ── 다음 이벤트           ┆ ┌┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 │ [╳] ▬▬ 모임 이름 ── 다음 이벤트           ┆ ┆ 가입한 모임이 없다는 안내
 │ …                                       ┆ ┆ [■ 모임 찾아보기 ]
 └────────────────────────────────        ┆ └┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
                                           ┆ ··· 누르면 P3 모임 찾기
                                           └────────────────────────────────
```

F1 모임 가입 신청과 심사 중 신청자 쪽 앞부분을 와이어플로로 그리면 이렇다.

```
 (모임에 가입하고 싶다)
   │
   ▼
 [P4 모임 페이지]                <로그인했는가?>             [M1 가입 신청서 (모달)]
 ├─ P4-3 행동 버튼 ─┐  가입 신청을   ┌── 예 ──────────────▶ ├─ M1-2 자기소개 입력 ─┐
 │ [■ 가입 신청 ] ──┼─ 누른다 ──▶ ◇                         │ [ 자기소개 ]        │
 └──────────────────┘              └── 아니오 ─▶ [X1 로그인·가입]                    │
                                                  │ F4 로그인 후 돌아온다 ──▶ M1   │ 자기소개와 참여 동기를 쓴다
                                                  ··· F4                          │   ┆ 조건: 자기소개 20자 이상 ┆
                                                                                  ▼
                                   [M1 가입 신청서 · 오류] ◀── 아니오 · 실패 ── <필수 항목을 다 채웠는가?>
                                                                                  │ 예
                                                                          ┌ 결과: 신청 완료 ┐
                                                                                  │
                                                                                  ▼
                                                                    [P4 모임 페이지 · 대기 중]
```

이 그림은 앞부분만 보인 것이다. 실제 와이어플로에는 오류 화면에서 다시 쓰고 분기로 돌아가는 화살표,
운영자 칸(가입 신청 알림 → P10 운영 콘솔 → 승인 분기), 심사 결과 분기와 두 목표 원까지 흐름 그림의 노드를 모두 옮긴다.
X1 로그인·가입 안의 화면은 F4 와이어플로에서 그리므로 F1에서는 프레임 하나로 두고, 동작 주석에 F4를 적었다
(유저 흐름 가이드에서 다른 흐름을 거칠 때 그 흐름의 첫 화면 노드 하나로 두는 규칙과 같다).
X1에서 M1로 가는 화살표 위의 "F4 로그인 후 돌아온다"는 흐름 그림의 선 라벨을 그대로 옮긴 것이다.
"자기소개와 참여 동기를 쓴다"는 섹션 번호가 없는 유저 입력이라, sitemap.md "담는 내용"에서 자기소개를 담는
M1-2 섹션을 찾아 거기서 화살표를 출발시켰다. 그 옆 점선 메모 박스는 흐름 그림의 주석 노드를 옮긴 것이다.

## 번호 규칙

```
프레임:     사이트맵 페이지 번호와 이름을 그대로 쓴다 (P4 모임 페이지, M1 가입 신청서, X1 로그인·가입).
            페이지 이름을 바꾸지 않는다
섹션 박스:   사이트맵 섹션 번호를 그대로 쓴다 (P4-3 = P4 페이지의 3번 섹션).
            박스가 쌓이는 순서는 섹션 번호 순서와 같다
공통 섹션:   사이트맵 "공통 섹션" 표의 이름을 쓰고 [공통]을 붙인다. 페이지 안에서는 그 페이지의 섹션 번호를 함께 쓴다
            (P4-1 헤더 [공통])
상태 화면:   페이지 이름 뒤에 " · 상태 이름"을 붙인다 (P4 모임 페이지 · 비로그인, P9 내 모임 목록 · 빈 목록).
            상태 이름은 유저 흐름 가이드 "화면 상태" 표의 여섯 가지 중 하나다
와이어플로:  유저 흐름 번호를 그대로 쓴다 (F1, F2 …). 새 흐름 번호를 만들지 않는다
요소:       번호를 붙이지 않는다. 가리킬 때는 섹션 번호와 요소 이름으로 가리킨다 (P4-3의 가입 신청 버튼)
기능:       ui-spec의 번호를 그대로 쓴다 (핵심 1~N, 보조 s1~sN). 새로 매기지 않는다
사이트맵에 없는 섹션이나 화면: 번호를 붙이지 않고 "(추가 후보) 이름"으로 적는다.
            번호는 사이트맵에 반영된 뒤 사이트맵 단계가 붙인다
```

## 그릴 때 지키는 규칙

```
- 섹션 목록의 섹션 하나에 박스 하나를 그린다. 목록에 없는 박스를 더 그리지 않고, 목록에 있는 섹션을 빼지 않는다
- 섹션 안의 요소는 사이트맵 섹션 목록의 "담는 내용"에 적힌 것만 그린다
- 색을 쓰지 않는다. 흰색, 검정, 회색만 쓴다. 그림자, 둥근 장식, 그라데이션을 쓰지 않는다
- 실제 문장을 쓰지 않는다. 버튼·탭·메뉴의 이름과 요소 이름만 글자로 쓰고, 본문은 가로줄로 그린다
- 공통 섹션은 한 번 그린 모양을 모든 페이지에서 그대로 다시 쓴다. 페이지마다 조금씩 다르게 그리지 않는다
- 같은 틀로 여러 개 생기는 페이지(템플릿)는 한 번만 그린다 (모임 페이지는 모임마다 하나지만 프레임은 하나)
- 첫 화면(스크롤 전에 보이는 부분)의 경계를 프레임에 가로 점선으로 표시한다.
  핵심 행동 버튼(진한 회색으로 채운 버튼)이 이 선 아래에 있으면 결정 기록에 이유를 남긴다
- 경쟁사 화면을 참고했으면 참고한 섹션에 출처(shots.md 파일명)를 적는다. 경쟁사의 섹션을 우리 섹션 목록에 없는데 가져오지 않는다
```

## 표현 형식

산출물은 HTML 파일 한 장이다. 브라우저로 바로 열리고, 인터넷에 연결되지 않아도 똑같이 보여야 한다.

```
- 외부 파일을 불러오지 않는다. 글꼴, CSS 라이브러리, 스크립트, 이미지를 모두 쓰지 않는다
  (이미지 자리는 CSS 테두리나 인라인 SVG로 X자를 그린다)
- 스타일은 파일 안의 <style> 하나에 둔다. 와이어플로의 화살표와 마름모는 인라인 SVG로 그린다
- 쓰는 색은 흰색, 검정, 회색 두세 단계뿐이다
- 앱이면 프레임 폭을 360px로, 웹이면 1280px 화면을 절반 크기(640px)로 줄여 그린다.
  사이트맵의 플랫폼이 "둘 다"이면 두 프레임을 나란히 그리되, 열 배치가 같은 페이지는 앱 프레임만 그리고 "웹도 같은 배치"라고 적는다.
  상태 화면과 와이어플로는 앱 폭 하나로만 그린다.
  웹 프레임에서 한 섹션 안에 여러 열로 놓인 요소는 앱 프레임에서 한 열로 접어 위에서 아래로 쌓는다.
  섹션이 쌓이는 순서는 두 프레임 모두 섹션 번호 순서 그대로다
- 기본 모양 프레임 안의 섹션 박스에는 섹션 번호를 id로 붙인다 (id="P4-3"). 클로드 디자인과 수정을 주고받을 때
  번호로 가리키기 위해서다. 상태 화면과 공통 섹션 영역의 id, 플랫폼이 둘 다일 때 웹 프레임의 id,
  id를 붙이지 않는 곳은 워크플로 "wireframe.html 구조"에 있다.
  같은 id가 파일 안에 두 번 나오지 않게 한다
```

HTML 안에서 프레임 하나는 이런 모양이다.

```html
<section class="frame" id="P4">
  <h3>P4 모임 페이지 <small>상세, 템플릿</small></h3>
  <div class="sec" id="P4-1"><span class="label">P4-1 헤더 [공통]</span> …</div>
  <div class="sec" id="P4-2"><span class="label">P4-2 모임 정보 <small>기능 6</small></span>
    <div class="bar title"></div><span class="name">모임 이름</span>
    <div class="line"></div><div class="line short"></div>
  </div>
  <div class="sec" id="P4-3"><span class="label">P4-3 행동 버튼 <small>기능 4, 11</small></span>
    <span class="btn">팔로우</span><span class="btn primary">가입 신청</span>
  </div>
  <div class="fold"></div>  <!-- 첫 화면 경계 -->
  …
</section>
```

파일 안에서 무엇을 어떤 순서로 싣는지(공통 섹션, 페이지별 프레임, 와이어플로, 대조 결과)는 워크플로의 Output에서 정한다.
