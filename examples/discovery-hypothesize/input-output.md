# discovery-hypothesize — 실행 예시

실행 대상: 크루 매거진 커뮤니티 앱 (2026-09-18 실행, 원본: `try_project_discovery_2/planner/260918-1754-crew-magazine-community-app/hypothesize/`)

## 호출

```
/dk-discovery-bundle:discovery-hypothesize Pass: 2
```

`Pass: 2`는 brainstorm 산출물이 이미 있을 때 쓰는 표준 모드다. brainstorm의 기회·영역을 "경쟁사가 충족하지 못하는 것"(Pass 1) 결과로 재사용하고, 이 단계에서는 "경쟁사가 잘하고 있어 유저가 실제로 쓰는 것"(Pass 2)을 찾은 뒤 세 종류 가설로 정리한다.

## Input

| 파일 | 이 단계에서 쓰인 방식 |
|------|---------------------|
| `init/seed.md` | 상위 기획 가설의 출발점. 핵심 고객 정의 두 문장이 상위 1·2가 되었다 |
| `research/references.md`, `research/analysis/*.md` (5개) | Pass 2에서 "유저가 돈이나 시간을 쓰는 지점"을 찾는 원자료 |
| `research/screenshots/*/shots.md` (5개) | analysis 주장과 대조하는 화면 기록. 어긋나면 화면 기록을 우선한다 |
| `brainstorm/brainstorm.md` | Pass 1 결과로 재사용 (기회 7 · 영역 4) |
| `brainstorm/needs-research.md` | 조사 항목 6건을 넘겨받아, 살아남은 가설 기준으로 다시 연결 |

## Output

```
hypothesize/
├── hypotheses.md        # 용어 정의 · 요약 표 · 상위 3 · 하위 7 · 카드 10 · Pass 2 니즈 목록 · 근거 쟁점 · Critic 기록
├── needs-research.md    # 조사 항목 6건 (각 항목에 "결과에 따라 무엇이 바뀌는지" 명시)
├── handoff.json
└── trial-notes.md
```

`handoff.json` 요약:

```json
"pass_mode": "2",
"upper_hypotheses": 3,
"lower_hypotheses": 7,
"cards_count": 10,

"by_evidence_level": { "상위": { "데이터": 2, "추론": 1 }, "하위": { "데이터": 4, "추론": 3 } },
"needs_research_items": 6,
"contradictions_found": 2
```

### 세 종류 가설의 뜻 (hypotheses.md 상단 용어 정의 발췌)

| 용어 | 뜻 |
|------|-----|
| 종류 — 상위 기획 가설 | "누가 무엇을 원하는가"에 대한 수요 명제. 서비스가 존재할 이유. |
| 종류 — 하위 기획 가설 | 기능이 통하려면 유저에 대해 참이어야 하는 심리·조건 명제. |
| 종류 — 기능 가설 카드 | 그 조건을 충족하기 위해 무엇을 만들면 되는지에 대한 화면·기능 수준의 가설. |
| 분류 — 기본기 | 경쟁 서비스가 모두 제공하고 있어서, 없으면 유저가 떠나는 기능. |
| 분류 — 차별화 | 경쟁 서비스가 제공하지 않아서, 우리가 제공하면 이기는 근거가 되는 기능. |
| 분류 — 미검증 | 유망해 보이지만 유저가 실제로 원한다는 증거가 아직 없는 것. 조사 대상. |

### 상위 기획 가설 하나

### 하위 기획 가설 하나

> ### 하위 1: "이 모임에 가면 시간을 낭비하지 않는다"는 확신이 서야, 신중한 가입자가 지원서를 쓰고 첫 모임에 나간다 (근거 수준: 추론, 연결 카드: 1·2·5)
> - 근거: 첫 모임이 기대와 달랐다는 불만은 후기로 확인된다 — 문토 첫 참여 불만 (analysis/munto.md 약점 3), 트레바리 첫 모임 후 이탈 (analysis/trevari.md 약점 4). 불만 자체는 확인된 사실이지만, "실체를 미리 보여주면 확신이 생겨 지원서를 쓴다"는 연결은 아직 확인 안 된 가정이다 → 조사 항목 1.

### 기능 가설 카드 — 분류별로 하나씩

**차별화** (카드 7, 전문):

> ### 가설 7: 콘텐츠 발행 = 운영자의 무료 모집 채널
> - 니즈: 크루 운영자는 새 멤버에게 도달하기 위해 시간과 돈을 쓴다
> - 가설: 매거진 발행이 측정 가능한 모집 효과(팔로우→지원)를 내면, 운영자는 과금 없이도 발행을 지속할 것이다
> - 설명: 모집·운영에 운영자가 돈을 낸다는 증거가 국내외에서 확인된다 — 소모임 월 15,500~42,000원, Meetup $23.99/mo~. 양쪽 모두 가격 불만이 확인되어, 더 싼 대안을 원하는 신호가 있다. 단 돈을 내는 쪽이 유료 호스트·개설자라, 무료 취미 크루 운영자도 같은 강도로 모집을 원하는지는 별개 문제다.
> - 근거: analysis/somoim.md 약점 2 (이용권 가격 장벽); analysis/meetup.md 약점 1 (2024.06 인상 후 "너무 비싸다", 활성 그룹 감소 정서 — Trustpilot·Reddit); analysis/munto.md BM (유료 정산 호스트 1,952명 — 모집이 수익과 직결되는 운영자층 존재)
> - 분류: 차별화
> - 연결 가설: 상위 2 / 하위 6·7
> - 출처: Pass 1 기회 3 + Pass 2 니즈 6·7 + seed (매거진 = 크루 포트폴리오)
> - 검증 신호: 크루당 월 매거진 발행 수의 유지율(3개월); 매거진 조회→지원서 기여율을 운영자에게 보여줬을 때 발행 빈도 변화
> - 조사: needs-research 항목 2 (현행 기록·홍보 채널)·항목 4 (돈을 낼 지점)

**기본기** (카드 2, 분류 행만):

> - 분류: 기본기 — 근거는 "경쟁사가 만들어 놓았다"는 사실뿐이지만, 직접 경쟁 3사가 모두 제공하고 대규모 실사용(소모임 500만 다운로드·Meetup 수천만 멤버)이 확인되는 요소는 그 사실만으로 수요가 입증된 것으로 본다

**미검증** (카드 5, 설명 행만):

> - 설명: 확인된 것은 경쟁사 쪽 사정뿐이다 — 문토·트레바리는 SPA라 본문이 검색에 잡히지 않고, 소모임 웹은 열람 전용이다. 유저가 검색으로 모임을 찾는다는 증거(검색량)는 수집하지 못했다. 경쟁사에 없다는 사실이 유저가 원한다는 증거는 아니므로 미검증으로 분류한다.

### 근거 쟁점 (analysis와 화면 기록이 어긋난 곳)

> - **쟁점 1 (소모임)**: analysis/somoim.md 약점 4는 "가입 전 판단 재료가 소개글뿐"이라 하나, screenshots/somoim/group-detail.png 는 멤버 33명·정모일정·운영진·게시판/사진첩/채팅 탭까지 웹 공개를 보여준다 …(생략) 유효하게 남는 주장은 "활동 기록이 발견 피드·검색으로 유통되는 콘텐츠는 아니다"로 좁혀진다.

### 조사 항목 하나 (needs-research.md "항목 6")

brainstorm의 조사 항목과 달리, 조사 결과에 따라 어떤 가설의 분류가 어떻게 바뀌는지를 적는다.

> ### 항목 6: 사람들이 취미 모임·크루를 검색으로 얼마나 찾는가 (검색량 확인)
> - 관련 가설/카드: 카드 5 (미검증)
> - 판정 변경: 검색량 확인("러닝크루", "독서모임 후기", "{지역} 취미 모임" 등) 시 미검증→차별화로 올림 / 미미하면 웹 공개는 부가 기능으로 내림
> - 조사 방법: 네이버 검색광고 키워드 도구·구글 키워드 플래너로 관련 키워드 월간 검색량 확인. …(생략)
> - 우선순위: 중간 — 카드 5의 분류 재판정에 직접 필요

brainstorm 항목 6(35세 이상 세그먼트)은 해당 기회가 카드가 되지 못해 버려졌다.

## 참고

- 같은 날 세 번 실행되었다. `142f2ba`(첫 실행, 가설 10개), `9f2b4fa`(워크플로 v1.1 — 상위·하위·카드 세 종류 구조 도입), `14c852e`(언어 규칙 적용 재실행)이다. 마지막 실행은 내용 판단은 그대로 두고 표현만 고쳤다. 예를 들어 카드 6 제목 "심사제 + 공개 기록의 저비용 진정성 필터"가 "무료 지원서 심사 + 공개 활동 기록으로 멤버 진정성 거르기"로 바뀌었다 (Critic 반영 기록 8~14번, 언어 위반 7건).
- 비대화형으로 실행된다. 워크플로상 "추론" 태그가 붙은 가설은 사용자 검수 대상이지만, 질문할 수 없어서 전부 needs-research 판정 대상에 넣는 것으로 대신했다 (v1.1 첫 실행 trial-notes). 사용자 판단은 다음 단계인 value-proposal의 채택 대화에서 받는다.
- 요약 표에서는 "카드 N"이라 부르고 본문 제목은 "가설 N"으로 되어 있다. 같은 번호가 같은 카드를 가리킨다. 다음 단계의 seed-v2.md도 "가설 N"으로 이 카드를 참조한다.
