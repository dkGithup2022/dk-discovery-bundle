# discovery-brainstorm — 실행 예시

실행 대상: 크루 매거진 커뮤니티 앱 (2026-09-18 실행, 원본: `try_project_discovery_2/planner/260918-1754-crew-magazine-community-app/brainstorm/`)

## 호출

```
/dk-discovery-bundle:discovery-brainstorm
```

`Criteria:` 인자 없이 기본 Critic 기준으로 실행했다. 산출물 커밋은 2026-09-19 (`efed21c discovery(brainstorm-trial): 기회 7·영역 4 — 추가조사 Y`).

## Input

| 파일 | 이 단계에서 쓰인 방식 |
|------|---------------------|
| `init/seed.md` | 아이디어·핵심 고객·제공 가치 원문. 모든 기회의 "seed 연결" 필드를 이 문서에 대조해 판정한다 |
| `research/references.md` | 분석 대상 5개 서비스 목록 (직접 경쟁 3: 문토·소모임·Meetup / 간접 경쟁 2: 오운완·트레바리) |
| `research/analysis/*.md` (5개) | 서비스별 강점·약점·가격 분석. 약점 항목이 "약점 — 출처" 형식이라 그대로 근거 필드에 인용된다 |
| `research/screenshots/*/shots.md` (5개) | 화면 캡처 기록과 캡션. analysis의 주장이 실제 화면과 맞는지 확인하는 데 쓰였다 |

입력으로 쓰인 seed 원문은 다음과 같다.

> 크루(소모임)가 활동 기록을 매거진(아티클)으로 발행하고, 유저는 콘텐츠를 읽다가 마음에 드는 크루를 팔로우·가입하는 콘텐츠 퍼스트 커뮤니티 앱.
> …(생략)
> 매거진에 좋아요·스크랩·팔로우가 붙어 크루 성장 지표가 된다. 커뮤니티 탭(가입인사/크루원 모집/일상)이 라이트 유저의 진입로. 크루 가입은 심사제(지원서) 기반.

## Output

```
brainstorm/
├── brainstorm.md        # 기회 7개 + 가능 영역 4개 + 유망도 요약 표
├── needs-research.md    # 추가 조사 항목 6개 (우선순위 높음 2 · 중간 3 · 낮음 1)
├── handoff.json         # 다음 단계(hypothesize)가 읽는 요약 데이터
└── trial-notes.md       # 실행 중 생긴 마찰과 Critic 반영 기록
```

### 기회 하나의 전체 형태 (brainstorm.md "기회 1")

기회는 경쟁 서비스에서 발견한 빈틈이다. 각 기회에 유형·출처·근거·seed 연결·유망도가 붙는다.

> ### 기회 1: 가입 전 "실제 활동"을 보여주는 발견 채널 부재
> - 유형: 시장 빈틈
> - 출처: analysis/munto.md 약점 4 + analysis/somoim.md 약점 4 + analysis/meetup.md 약점 4 (직접 경쟁 3사 공통)
> - 설명: 직접 경쟁 3사 모두 가입 전 판단 재료가 소개글·이벤트 리스트 수준이다. 모임의 활동 기록이 외부에 공개 콘텐츠로 축적·유통되는 구조는 3사 어디에도 없다.
> - 근거:
>   - 문토 — "가입 전에 모임 내부 활동을 볼 수 있는 수단이 약함 — 활동 기록이 외부 공개 콘텐츠로 축적되지 않음" (analysis/munto.md). 스크린샷: screenshots/munto/entry-login.png — 라운지(멤버 피드)는 비로그인 접근 불가, 로그인 화면으로 강제 진입. …(생략)
>   - 소모임 — 반례에 가까운 예외: 웹 모임 상세가 멤버·정모일정·게시판 탭까지 공개해 "가입 전 판단 재료가 경쟁사 중 가장 풍부" (screenshots/somoim/shots.md, screenshots/somoim/group-detail.png). 단, 이는 모임 단위 페이지 안의 구조 공개이고, 활동 기록이 발견 피드·검색으로 유통되는 콘텐츠는 아니다 …(생략)
> - seed 연결: seed의 발견→기록→연결 순환이 정확히 이 지점을 다룬다. …(생략)
> - 유망도: 높음
> - 유망도 이유: seed와 직접 연결 + 3사 analysis·스크린샷에서 구조 부재 확인 + 매거진 발행이 seed 핵심 기능. 단, "구조가 없다"는 공급 측 확인이며 사용자가 이를 불만으로 표현하는지는 미확인 (needs-research 항목 1).

### 가능 영역 하나의 형태 (brainstorm.md "영역 4")

가능 영역은 seed를 어느 방향으로 넓힐 수 있는지에 대한 탐색이다. 기회와 달리 "확장 축"과 "원래 → 확장" 비교가 붙는다.

> ### 영역 4: 매거진의 웹 공개 = 검색 유입 채널
> - 확장 축: 커뮤니티/획득 채널 (기타)
> - 원래: 앱 내 발견 (콘텐츠를 읽다가 크루 팔로우·가입)
> - 확장: 매거진 아티클을 웹에 공개 색인시켜 검색 유입 → 크루 페이지 전환의 획득 채널로 사용
> - 근거: 직접 경쟁 3사의 웹 개방도가 낮다 — 문토는 SPA로 "본문 대부분 미렌더링" (analysis/munto.md 접근 실패 기록), 라운지는 로그인 장벽 …(생략)
> - 유망도: 높음
> - 유망도 이유: seed의 핵심 산출물(매거진)을 그대로 쓰는 확장이라 추가 개발이 작고, 경쟁 3사의 공백이 수집 데이터(접근 실패 기록·스크린샷)로 직접 확인된다. 단 취미 모임 관련 검색량 자체는 미확인.

## 참고

- 이 실행은 `v1-brainstorm` 명령이 정식으로 만들어지기 전에 시험 실행으로 돌았다 (산출물 커밋 `efed21c`, 명령 추가 커밋 `eda42bd`는 같은 날 그 뒤). 그래서 `handoff.json`의 `tool` 필드가 `project_discovery:hypothesize-trial`로 남아 있고, 추가 조사(additional-research)도 자동 실행하지 않았다.
- 스크린샷은 주장을 보강하는 것보다 주장을 반박하는 쪽에서 더 쓸모가 있었다. trial-notes.md는 소모임 화면 기록이 analysis의 "판단 재료가 소개글뿐"이라는 주장을 뒤집은 사례를 들며, analysis 약점과 스크린샷 기록을 대조하는 체크를 다음 단계에 넣자고 제안했다. 이 제안은 hypothesize의 "근거 쟁점" 섹션으로 반영되었다.
- 다음 단계는 `discovery-hypothesize`를 `Pass: 2`로 호출하는 것이다. 이 단계의 기회·영역·조사 항목이 hypothesize에서 Pass 1 결과로 그대로 재사용된다.
